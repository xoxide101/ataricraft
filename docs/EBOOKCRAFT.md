# EBookCraft - ebook reader and book/scan converter

`web/ebookcraft.html` (home menu: **EBookCraft**, opens in a new tab) plus `scripts/ebookcraft.cjs` (CLI). It is a Craft app with two halves that share one engine:

* **Reader** - opens a book, paginates it, keeps your place, and can show the same text as an 8-bit "Atari view".
* **Convert & deploy** (the production side) - takes a book, a PDF or scanned page images and produces OCR text, 1-bit / 2-bit / 4-bit / 8-bit page images, Craft text, an Atari boot disk with a viewer, a bundle and a library layout.

Everything is offline vanilla JS, no build step, no CDN, no network at run time.

## Formats (reader and converter input)

| Format | Status |
|---|---|
| EPUB 2/3 (zip + XHTML, OPF spine, NCX/nav TOC) | yes; own unzip, DEFLATE through `DecompressionStream` (browser) or `zlib` (Node) |
| Plain text, Markdown, HTML/XHTML | yes (chapters split at headings) |
| FB2 (FictionBook) | yes, including embedded images listed as `[image]` |
| MOBI / AZW / PRC | MOBI6 with PalmDOC (type 2) compression. **Not supported:** DRM, HUFF/CDIC compression, KF8-only AZW3 (those report a clear error) |
| XCW/CWD (Craft Word), DOCX, RTF | yes, through the xCWriter core (`XCW.openDoc`) |
| PDF with a text layer | yes: own parser (xref/object streams, Flate, ToUnicode CMaps), reading order by position |
| PDF scans | page images are decoded directly (Flate/DCT JPEG/raw). In the browser the pdf.js module vendored for the PDF viewer (`PDFENGINE` from `web/js/pdfjs/pdfengine.js`, loaded by `ebookcraft.html` and assigned to `EBC.pdf.engine`) rasterises any page; if those files are absent the engine is null. **Not supported without pdf.js:** CCITT, JBIG2, JPX, LZW images; encrypted PDFs |
| Images: PNG, JPEG (baseline + progressive), BMP, PBM/PGM/PPM | yes; several images = several pages in name order |
| `.ebookcraft.zip` bundles | yes (the output of the converter re-opens in the reader) |

No DRM is handled or circumvented. Use your own or public-domain books.

## Reader

Open a file (button, drag and drop, or `ebookcraft.html?book=<url>`). Left panel: **Contents**, **Bookmarks**, **Search**, **Shelf** (books opened in this browser, plus the library `index.json`). Toolbar: previous/next, `A-`/`A+`, face (Serif/Sans/Mono and the Craft font list from `XFACE` when `faces.js` is present), Day/Sepia/Night, 1 or 2 columns, **Page / Atari view**, bookmark.

Keys: Left/Right/PageUp/PageDown/Space turn pages, `B` bookmark, `N` night, `/` search.

Atari view draws the book through `EBC.book.toLines` (64 columns) and `EBC.atari.textPage` in the 4x7 Craft font: 320x192, 23 text rows under a status bar, exactly the screens the generated Atari viewer shows.

Storage (browser only): `localStorage` `ebc.settings`, `ebc.pos.<bookid>` (chapter + block index, so the position survives font and window changes), `ebc.bm.<bookid>`; IndexedDB `ebookcraft/books` for the shelf.

## Converter

Choose files, tick what you want, **Convert**. Outputs (all in `result.files`, previewable and downloadable; the CLI writes the same tree):

```
pages/atari-bw|gray4|gray16|gray256/pNNN[-tNN].png    320 / 160 / 80 x 192 style (scans may be cut into -tNN screens)
pages/print-bw|gray4|...         /pNNN.png            high resolution (default 1700 px wide)
text/book.txt  text/book.xcw  text/pNNN.txt           (OCR text per page for scans)
atari/<slug>-view.atr                                   boot disk: viewer + every page, no DOS needed
atari/<slug>-view.xex                                   DOS-style viewer with the first 3 screens
atari/<slug>-text.atr                                   DOS 2 disk with BOOK.TXT
manifest.json  <slug>.ebookcraft.zip                    bundle (manifest + pages + text)
```

* **1-bit** with `threshold`, `bayer4`, `bayer8`, `floyd` (Floyd-Steinberg) or `atkinson` dithering; contrast, brightness, gamma, auto levels, optional **deskew**, margin **crop**, background **flatten** (removes page shading before thresholding).
* **More**: 4 gray (GR.15, 160x192), 16 gray (GR.9, 80x192), 256 gray (PNG only; the Atari has no 256-gray mode). 1-bit is GR.8 (320x192).
* **Text**: books give `book.txt`/`book.xcw` (XCW export truncates at the Craft Word limit and says so; `book.txt` is always complete). Scans give OCR text when OCR is on.
* **Atari viewer** (`tools/ebookcraft/viewer.asm`, MADS; generated bytes in `ebc-viewer-data.js` via `node tools\ebookcraft\build-viewer.cjs`). The boot ATR is 128-byte sectors, 60 sectors per 7680-byte screen; 720 sectors hold 11 pages, 1040 hold 17, larger books get a custom size up to 65535 sectors. The XEX holds 3 pages only; the ATR holds all. Viewer keys: see the viewer source header.

### Deploy

`Deploy: server-layout zip` (and CLI `--deploy` / `--stage DIR`) writes `library/craftapps/EBookCraft/<slug>/...` plus a shelf `library/craftapps/EBookCraft/index.json`, the layout `docs\DEPLOY.md` describes (`library\craftapps\*` is listed by the main app). `--deploy` copies into this repo's `web\library`; `--stage DIR` writes the same tree anywhere so `scripts\deploy-server.ps1` can pick it up. Nothing here touches the real server. `deploy-server.ps1` also stamps `ebookcraft.html`.

## CLI

```
node scripts\ebookcraft.cjs convert <input...|folder> --text --bw --gray 4,16,256 --dither atkinson --out out\book
node scripts\ebookcraft.cjs convert scan.pdf --ocr --deskew --tiles 2 --out out\scan --deploy
node scripts\ebookcraft.cjs info book.epub        # title, format, chapters, warnings
node scripts\ebookcraft.cjs ocr-status
```

The full option list is at the top of `scripts/ebookcraft.cjs`.

## OCR add-on

OCR is **optional and not committed**. It uses [tesseract.js](https://github.com/naptha/tesseract.js) 7 (Apache-2.0) with the Tesseract WASM core and the English `tessdata_best` LSTM model (Apache-2.0), all run locally; no CDN is ever contacted.

```
node scripts\ebookcraft-install-ocr.cjs         # needs npm once; --from <dir> reuses an existing node_modules
```

It copies the files into `web/js/ebookcraft/ocr/` (browser, about 22 MB: worker, WASM core variants, `eng.traineddata.gz`) and `tools/ebookcraft/ocr/` (Node). Both directories are git-ignored; `deploy-server.ps1` copies `web\js` as usual so a staged server includes the add-on if you installed it. Without it every other feature works, and the UI says so. Page clean-up (flatten, deskew, contrast) runs before recognition; line-wrapped OCR is reflowed into paragraphs by `EBC.ocr.reflow`.

## Code map (blueprint for other Craft apps)

`web/js/ebookcraft/*` are UMD modules (`window.EBC` in the browser, `require()` in Node via `index.js`), so the UI, CLI and tests run the same code.

| File | Role |
|---|---|
| `ebc-base.js` | bytes, CRC32, inflate/deflate, zip read/write, PNG encode/decode, text decoding, HTML tokenizer |
| `ebc-image.js` | gray images, PNG/JPEG/BMP/PNM decode, resize/fit/tiles, flatten, deskew, crop, quantize + the 5 dithers |
| `ebc-pdf.js` | PDF parser: text extraction, embedded page images, `EBC.pdf.engine` hook |
| `ebc-book.js` | all book readers -> `{title,author,chapters:[{title,blocks}],toc,resource()}`; `toLines`, `paginateLines`, `search` |
| `ebc-atari.js` | text screens, GR.8/15/9 packers, boot ATR, XEX, DOS 2 text disk |
| `ebc-viewer-data.js` | generated: assembled viewer (do not edit; rebuild with `tools\ebookcraft\build-viewer.cjs`) |
| `ebc-ocr.js` | tesseract.js wrapper (browser worker or Node), page preparation, reflow |
| `ebc-pack.js` | `convert()` pipeline, bundle, `openBundle`, deploy helpers |
| `ebc-reader.js` / `ebc-app.js` | browser reader engine / page wiring |

Conventions followed from xCWriter: one self-contained `web/<app>.html`, only relative URLs, scripts loaded in the page (no bundler), state in `localStorage`, `docs/<APP>.md`, a CLI in `scripts/`, tests in `scripts/*-test.cjs`, and `deploy-server.ps1` stamping. Another Craft app should copy that shape: engine modules first, UI last, nothing in the engine that touches the DOM.

## What was run, and limits

Run and passing here: all Node tests including OCR (about 95 % mean confidence on the rotated, shaded sample scan, about 2 s); the Playwright browser test in Chrome including browser-side OCR and a scanned PDF through pdf.js; the boot ATR and the XEX both start in the emulator and show page 1 of the sample book, and SPACE turns to page 2 on the ATR (130XE, OS ROM).

Not verified: the other viewer keys and the XEX page turn, the DOS 2 text disk in a real DOS, real-hardware behaviour, MOBI/FB2/EPUB files from the wild (only the generated samples and typical structure), large books (tens of MB) for speed, JPEG variants beyond the samples (progressive and CMYK are implemented but only lightly tested), non-English OCR (install more `tessdata` into the add-on directory yourself). Fonts: the face list uses system fonts and the Craft font picker when `faces.js` is available; no personal fonts are bundled.
