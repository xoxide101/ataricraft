# ACWriter PAGE mode (Stage 4)

A second view next to the normal 5px/64-column editor. The normal view is untouched: same code paths,
same typing latency (`mfull`/`mscr`/`mkey` meters at `$A0`/`$A1`/`$A2` are in the Latency section below, identical to the
pre-PAGE build).

## Use

`Esc`, `L` (Layout menu), then:

| Key | Command |
|---|---|
| V | enter / leave PAGE mode (document stays intact) |
| P | paper: Letter, A4, Legal |
| T | pitch: 10, 12, 17 cpi (resets the default margins) |
| L / R | left / right margin +1 column (wraps at 10) |
| 1 / 2 / 3 | set a left / centre / right tab stop at the cursor column |
| X | clear all tab stops |

`Tab` (the Atari Tab key, `$7F`, or Ctrl-I) pads with spaces to the next tab stop, else the next multiple of 5.
All three stop kinds act as left tabs when typing (centre / right alignment is drawn on the ruler only).

## File format

Save As writes the CPG1 trailer (flags bit 1, [PAGE.md](PAGE.md)) with paper, pitch, margins (top/bottom 6) and up to 8 tab stops; Open restores them, and ignores unknown records. Files without a trailer keep the defaults. `scripts\acwriter-page.cjs` proves the round trip through `craftdoc.cjs`.

## What it shows

* 4px cells, 12-row Craft lines (2px headroom, cap row, x-height, baseline, 3px descender rows).
* Wrapping at the page usable width (paper columns minus margins): Letter/Legal 85/102/144 columns at 10/12/17 cpi,
  A4 82/99/140. The page is wider than the 80 cells of the screen, so the view scrolls horizontally with the cursor.
* Ruler row: margins, page centre mark and L/C/R tab stops. Status row: line, column, page, paper, pitch, margins
  and a mini page navigator (page box with a viewport marker).
* Glyph planes (`craftpg.inc`, generated by `mkpgfont.cjs`) carry the descender rows.

## Memory

Machine tiers (detected at startup; the startup message is "Needs 128K (130XE); uses more if found"):

| tier | detection | behaviour |
|---|---|---|
| 64K | `bk_det`: no separate bank at `$4000-$7FFF` (`sv_xe = 0`) | the old view works; PAGE, zoom, fonts and the dictionary need banks, so they show message 39 |
| 128K (130XE) | `bk_cnt`: 4 distinct banks | baseline: dictionary in bank 1, overlay images in bank 2, font charsets in bank 3 |
| expanded (Rambo / Compy-Shop 320K, 576K, 1MB) | `bk_cnt`: 16 or 32 banks, stored in `sv_nb` (`$07E5`) | the count is detected and kept; **nothing uses banks above 3 yet**, so extra RAM gives no extra capacity today |

`bk_cnt` writes a signature to `$4000` under every PORTB bank-bit combination (bits 2,3,5,6,7), counts distinct signatures and restores the bytes. `scripts\acwriter-banks.cjs` runs it on the emulator's 64K, 128K, 320K (Rambo and Compy-Shop), 576K and 1088K settings: it reports 1, 4, 16, 16, 16, 32 banks. The 576K setting reports 16 because that machine's extra bank bits (PORTB bit 1 and others) are outside the probed set, so only the standard five bits are counted. This is verified in the emulator only; no real hardware was tried.

* Document area: `$6400-$8FFF` = **11,264 bytes** in every view; the old view's capacity check stops typing at the end (`scripts\acwriter-cap.cjs`).
* Page code (P), the font module (Z), edit (E) and spell (S) code are overlay images stored in bank 2 and run from the shared slot `SLA = $57B7` (the slot is 12 pages and must end at or below DOC = `$6400`, so ~73 bytes of resident growth remain) (the overlay manager is `ovl.inc`; `ovc` refuses E/S while P/Z is loaded and the view is PAGE). Image Z is staged at `$8000` because staging sources must be outside the `$4000-$7FFF` bank window and the images no longer fit `$BD00`.
* Bank 3 holds up to 4 loaded 1 KB charsets (4 pages each, `$40 + (slot-1)*4`).

## Zoom (2x) and fonts

PAGE mode has a 2x blow-up that draws the true 8x8 glyphs at 2x (16 px cells, 20 columns on screen, horizontal scroll and the mini navigator). 12x12 and 10x12 glyphs are **not** used on the Atari yet (no plane for them): the 6502 only has 8x8 plus the 4/5/6 px faces.

`Esc`, `C`, `F` (Character > Font; the Character menu has no visible label for this key yet) asks for a file name and loads a 1,024-byte `.FNT` Atari charset from disk or `H:` into the next free font slot, then applies it to the paragraph at the cursor. The font name is written as CPG1 tag 2 (paragraph 0) and tag 3 (`[paragraph lo, hi, name]`, one per change); `ROM` means the standard face. A font change only exists at a paragraph start, so a line never mixes fonts. On Open, tags 2/3 load the named files (looked up on the same device) before the first paint. Limits: 4 loaded fonts, 8 font changes; `.acf` files are not read directly (export `.fnt` from the font editor).

Typing in the old view is unchanged: `scripts\acwriter-latency.cjs` prints `mfull/mscr/mkey` (`$A0..$A2`) on the 130XE. History: `[34, 5, 5]` before the overlay work, `[77, 6, 7]` now. The change is explained, not a code regression: `mfull` is a full redraw of the start-up sample document, and until the overlap fix (see Segment overlaps) the sample was truncated by the home/convert text (353 then 594 bytes, `dend` = $6561/$6692); it is now the intended 1499 bytes (two `body` copies), so `mfull` scales with it. `mscr` (one `scrolldown` = 6144-byte block copy + one `drawdoc` line) is 5.5 jiffies of copying plus a line draw, so the longer sample text tips it over a one-jiffy boundary; typing latency (`mkey`) is within one or two jiffies. Compare builds only with the same sample length.

### 12x12 / 10x12 faces on the Atari: constraint analysis (not implemented)

Decision: **analysis only**; no partial is shipped, because every viable partial needs a new overlay image and there is no room for one without evicting existing features.

Numbers (from the current build):
* Overlay slot `SLA=$57B7`, 12 pages, must end at or below `$63B7` (DOC starts `$6400`, 11,264 bytes, fixed by the document-size requirement). It cannot grow. Image ends: E `$637A`, S `$5FEA`, R `$618A`, P `$63B1` (6 bytes spare), Z `$6357` (~96 bytes spare), H `$5C28`. The 2x view (Z) has no space for an unaligned blitter plus a layout pass.
* Resident code slack is ~73 bytes below `$6400`; each overlay stub costs ~9 bytes, plus a command entry and menu text.
* Low RAM is full: LDB/copy buffer `$9F00` (256 B), SCR `$A060-$BF9F`. Staging area in bank 2 uses E `$6A00`, H `$7600`, Z `$8000`, P `$A100`, S `$AD00`, R `$B500` (ends `$BFFF`); a seventh image has nowhere in the staging window without re-packing the existing six.
* Storage is **not** the problem: a 12x12 face is 96 glyphs x 12 rows x 2 bytes = 2,304 B (9 pages); 10x12 uses the same 2-byte rows. Bank 3 holds the 4 charset slots (4 KB, `$40..$4F` pages) and about 12 KB is free, i.e. 5 such faces.
* Rendering is the problem: a 12 px cell is not byte aligned on the 40-byte 1-bpp line (the 2x view relies on 8 px = 1 byte, 16 px = 2 bytes). Each glyph needs a 12-row shift/merge blit (~60 bytes of code) plus a column/layout routine for ~26 columns, cursor drawing, horizontal scroll and the style (bold/underline) passes, about 600-900 bytes in all.
* The loader differs: `fnload` reads a 1,024-byte `.FNT`; a wide face needs a new 2,304-byte format and a different font-table state/size byte.

Memory plan if the space is ever freed (e.g. by dropping the image-H home/convert text or moving S to a second slot):
1. New overlay image Y (id 6, <= 12 pages) with the 12-px view: pzmain-style loop, `ysh` blitter, loader for `.F12` files.
2. Stage Y at `$B500` after moving R down by shrinking nothing else; or re-stage P/S one page lower each (P has 6 spare bytes, so this only works after trimming P).
3. Wide faces in bank 3 pages `$50+` (2,304 B each, up to 5), selected by font-table byte 15 bit 7 (wide) with the existing CPG1 tag 2/3 names unchanged (name suffix `.F12`).
4. `ovc` guard `cmp #4` extended to the new id; `ovsp` and `cpx #7` in `ovlcopy.inc`; `NCMD` +1.

Until then the Craft 12x12 and 10x12 faces are used on the host side (web/PC rendering, bitmap printing is 8x8 Craft face only) and the Atari shows 8x8 doubled.

### Segment overlaps (scripts/xex-overlap.cjs)
Two overlaps reported by `xex-overlap.cjs` were real corruption, not overlay reuse, and are fixed: (1) `homedoc`/`convdoc` were assembled at `SLA+$0C00` = `$6225`, on top of the first 589 bytes of the sample DOC (`$6400`); they are now overlay image H (id 4, staged at `$7600`, run from the slot by `pgshow`; home and convert pages therefore need a 130XE like the editor does). (2) the spell dictionary access code (`spellbk`, `$9300-$947F`) overwrote `font4` planes f4_0/f4_1 (`$9400+`); it is now resident below `$4000`. The tool reports no overlapping segments.

## Not done / limits (honest list)

* **Sections and styles:** ACWriter shows the resolved face of every paragraph (document default, section font, Title/Heading style and paragraph override already folded into CPG1 tags 2/3 by xCWriter), within the existing 4 typeface slots and 8 font changes, in the 2x view only (pixel-identical to xCWriter's Atari 2x view, `scripts/acwriter-sections.cjs`). There is no section or style UI on the Atari: Character > Font (Esc C F) sets a face from the paragraph where it is chosen, which is the same section-like "in force until the next change" rule. No Layout > Style menu: the overlay and bank-3 budget has no room for it (see Memory above). Cell sizes other than 8x8 and style spacing are ignored on the Atari. ACWriter saves tags 1-3 only, so xCWriter's structure (sections, roles, sizes, style table, tags 4-7) is flattened to explicit paragraph faces when a file is saved from ACWriter; the faces stay identical.
* The font table follows paragraph numbers for Return, a joining Backspace, Cut/Paste of whole paragraphs, find/replace (paragraph count never changes; replacement text cannot hold a paragraph end), failed and successful Open and New (a CRFT file without font tags, a text file import, and New reset the table; a failed Open keeps it). Tested by `scripts/acwriter-fontpara.cjs` and `scripts/acwriter-fontfind.cjs`; `scripts/acwriter-facereload.cjs` covers save/reload with several typefaces. Find/replace starts at the cursor, so a replace from the middle of a document leaves earlier matches alone.
* Per-block fonts show only in the 2x view; the 1x PAGE view uses the 4 px face.
* No alignment, indent, bullet, bold/italic/underline rendering in PAGE mode (text only), and none in the 2x view either. Sub-script descenders are clipped.
* Centre/right tab stops only affect the ruler.
* Expanded memory is detected but unused (see tiers).
* Changing paper/pitch/margins changes soft wrap breaks stored in the document (the text is unchanged).

## Menu/status chrome face
The zoom-view header and status lines (and the menu bar) still use the Atari OS text-mode charset. Switching them to the Standard face needs a second text blitter in the resident area (about 0.3 KB for the blitter plus a 768-byte charset in a bank); the resident area and overlay slot are full, so this is not done. Status: not implemented.


## Cursor, redraw, status, fonts, version (0.1.5)

- **Cursor**: `word/cursor.inc`. A 5x8 XOR block blinks via RTCLOK in text mode (only its own cell toggles); it stays on while keys are pressed or idle. PAGE and zoom use a static XOR cursor.
- **No flicker**: typing/moving redraws the cursor line in place through the row buffer `RB` (`redrawcur`, `qrw`), never clearing first. Ruler and status rows also redraw in place. Full redraw only on scroll, reflow, join/delete line, menu close, or **Ctrl-T** (force redraw).
- **Status**: `Ln/Col` updates on every move; bottom right shows `Pg n/m Lnn`. Text mode uses lines per page 54/58/72 (paper 0/1/2); PAGE mode wraps differently, so its numbers follow the page layout.
- **Fonts**: text face defaults to Craft 5px (`font4.inc`), menus/status to Craft 6px (`font6.inc`); ROM remains selectable via Character > Font.
- **Memory**: the overlay slot `SLA..SLA+$C00` must end at or below DOC (`$6400`), i.e. `SLA <= $5800` (asserted in `poc5.asm`). Cursor helpers live in free pools (`$0489`, `$06C0`, `$1F55`); keep `xex-overlap.cjs` clean.
- **Version**: single source `word/version.inc`; shown on the start menu and Help; build script prints it and writes `ACWRITER.VERSION.txt`. Bump on every rebuild.
